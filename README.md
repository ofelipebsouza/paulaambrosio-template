# Paula Ambrosio Interiors

Premium editorial website for Paula Ambrosio Interiors — luxury interior design in Miami and South Florida.

**Stack:** Astro · TypeScript · Tailwind CSS v4 · MDX content collections · Vercel

## Commands

| Command           | Action                                    |
| ----------------- | ----------------------------------------- |
| `npm run dev`     | Local dev server at `localhost:4321`      |
| `npm run build`   | Production build (`dist/client` + `.vercel/output`), then the post-build guard |
| `npm run check`   | Post-build guard on its own (`dist/client`) |
| `npm run preview` | Preview the production build locally      |
| `npm run lint`    | Typecheck (`tsc --noEmit`)                |
| `npm run dns:check` | Audits MX/SPF/DKIM/DMARC of the mail path and prints what to publish |
| `npm run smtp:check` | Verifies the SMTP host, port and password the form uses (`--send` delivers a test message) |
| `npm run mail:test` | Integration test of both inquiry emails against a local SMTP sink |
| `npm run lead:test` | Sends a real test inquiry through a running site and interprets the answer |

`npm run build` fails if the output contains an unsafe form action, a plain-http
reference, more than one `<h1>`, a canonical that does not match the served URL, an
internal link that would redirect, a broken internal link, or an `/api/*` form
action that was not routed to a server function. That guard is what keeps Best
Practices at 100 — a `<form action="mailto:…">` on an HTTPS page is flagged by
Chrome as insecure form submission and drops the Lighthouse category to 77.

The contact endpoint requires the Vercel adapter, so the client build lands in
`dist/client/` and the deployable output in `.vercel/output/`; the guard picks the
right directory on its own. Details, environment variables and the Windows/OneDrive
build note: [`docs/contact-form.md`](docs/contact-form.md).

## Architecture

```
src/
├── config.ts              # Brand entity, contact, canonical URLs, nav (single source of truth)
├── lib/seo.ts             # Centralized SEO + JSON-LD schema builders
├── layouts/Layout.astro   # <head>: meta, canonical, OG/Twitter, fonts, entity schema graph
├── components/
│   ├── Header.astro / Footer.astro
│   ├── projects/ProjectGrid.astro
│   └── ui/                # Breadcrumbs, CtaBanner, FAQ (zero-JS details/summary)
├── content/
│   ├── projects/          # Case studies (MDX)
│   ├── journal/           # Articles (MDX)
│   ├── services/          # Service pages (MDX)
│   └── locations/         # Location pages (MDX)
├── pages/                 # Static routes; /projects /services /locations /journal + [slug]
└── styles/global.css      # Design tokens (@theme) + editorial primitives
```

- **Static output.** No server runtime. Deployed to Vercel via GitHub.
- **Content collections** with strict Zod schemas (`src/content.config.ts`) — invalid frontmatter fails the build.
- **SEO** is centralized: pages pass `title/description/canonical/ogImage` to `Layout.astro` and emit schemas from `src/lib/seo.ts` (Organization, Person, WebSite, WebPage, BreadcrumbList, Article, Service, FAQPage).
- **Redirects** from the previous Framer URL structure live in `vercel.json` (301s).
- **Sitemap** is generated by `@astrojs/sitemap` (`/sitemap-index.xml`); `public/robots.txt` points to it.
- **Fonts** are self-hosted in `public/fonts/` (preloaded woff2, no render-blocking third-party requests).

## Editing content (agent-safe)

All content lives in `src/content/**` as MDX with predictable frontmatter. The Zod
schemas are the contract — read them before writing content. Frontmatter fields:
`title`, `draft`, `featuredImage`, `imageAlt`, `seoTitle`, `seoDescription`, plus
collection-specific fields (`faqs`, `relatedServices`, `relatedLocations`,
`relatedProjects`, `gallery`, `services`, …). Set `draft: true` to keep a file out
of the build and sitemap.

Agent workflow (Hermes-compatible): branch → edit/create MDX → `npm run build`
(validates schemas + links) → commit → PR → Vercel preview → merge to `main`.

## Environment variables

The contact form posts to `POST /api/contact/`, a server-side Astro route that
validates the inquiry and delivers it over SMTP (Nodemailer). It is the only
on-demand route in the project — everything else stays statically generated.

| Variable | Required | Purpose |
| --- | --- | --- |
| `SMTP_HOST` | yes | `smtpout.secureserver.net` for GoDaddy Professional Email (Titan) |
| `SMTP_PORT` / `SMTP_SECURE` | yes | `465` / `true` (Titan) · `587` / `false` (Microsoft 365) |
| `SMTP_USER` | yes | mailbox that authenticates and signs every message |
| `SMTP_PASSWORD` | yes | mailbox password — **server only** |
| `CONTACT_RECIPIENT_EMAIL` | recommended | inbox that receives the leads (defaults to `SMTP_USER`) |
| `CONTACT_MAIL_MODE` | no | `json` writes the composed email to the server log instead of sending |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | no | distributed rate limiting |
| `PUBLIC_TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | no | Cloudflare Turnstile challenge |

Set them in Vercel (Production, Preview **and** Development) and redeploy: Astro
inlines `import.meta.env.*` at build time. Full architecture, DNS prerequisite and
testing procedure: [`docs/contact-form.md`](docs/contact-form.md).

No secrets belong in the repository: `.env`, `.env.local`, `.env.*.local` and
`.vercel` are gitignored, and `.env.example` is a template without values.

## URL contract

The site is served with `trailingSlash: true` (see `vercel.json`), so every route
ends with a slash: `/about/`, `/projects/home-ka/`. Canonicals, `og:url`, the XML
sitemap and all internal links use that exact form — anything else costs a 308
redirect. `src/config.ts` owns the helpers (`serviceUrl`, `locationUrl`,
`projectUrl`, `absoluteUrl`) and `npm run build` verifies it.

The canonical origin is `https://www.paulaambrosio.com` (`astro.config.mjs` `site`
and `SITE.url` in `src/config.ts`). The apex domain redirects to it in
`vercel.json`.
